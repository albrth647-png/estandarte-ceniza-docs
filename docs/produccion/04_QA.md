# 04 · QA — qué significa «terminado»

**Estado:** ✅ **aprobado por el dueño (aprobación en bloque, 2026-09-30). Documento final.**

> Una tarea **no está hecha** hasta que `npm run qa` está **verde**. Aquí está el contrato de
> calidad: qué se ejecuta, qué umbrales hay y qué se prueba por sistema.

---

## 1. La batería (`npm run qa`)

| Paso | Comando | Qué falla bloquea |
|---|---|---|
| **Tipos** | `npm run check` | `tsc` estricto sobre `js/`, `tools/`, `tests/` |
| **Tamaño** | `npm run tamano` | archivo > 500 líneas, o `data/`/`css/` por encima de su peso máximo |
| **Lint** | `npm run lint` | `js/**` sin Node (`process`/`require`), imports, estilo |
| **Datos** | `npm run validate` | JSON jugables + paridad ES/EN |
| **Enlaces** | `npm run docs` | enlaces relativos de markdown rotos |
| **Tests** | `npm run test:cov` | `node --test` + **cobertura ≥ 90 %** (≥ 95 % en `js/systems/` y `js/core/`) |
| **Humo** | `npm run smoke` | Chromium headless en **960×683** y **915×555** |
| **Vivo** | `npm run vivo` | recorrido real en Chromium: portada → menú → creación → exploración → guardar → recargar → opciones; 60 fps y **0 errores de consola** |

- **Todo verde** = la tarea cierra. **Un solo paso rojo** = no cierra.
- **Desde 2026-10-03** el QA incluye `vivo`: el «0 errores de consola» del recorrido es
  **automático** en cada tarea. Los **10 minutos** son la prueba manual del §4 y son
  **DoD de fase**, no de tarea.

---

## 2. Umbrales

| Umbral | Valor |
|---|---|
| Cobertura | **≥ 90 %** global · **≥ 95 %** en `js/systems/` y `js/core/` |
| Errores de consola | **0** en el recorrido (`vivo`, automático) · **0** en 10 min (prueba manual, §4) |
| Humo | 2 tamaños de pantalla, sin pantallas muertas |
| Paridad ES/EN | **cero** claves sin pareja |
| Enlaces de docs | **cero** rotos |

---

## 3. Qué se prueba por sistema

- **Sistemas puros** (`js/systems/*`): normal, borde y error, mínimo 3 casos (`../../AGENTS.md`).
  Memoria, Firma, prisioneros, favores, Crónica, economía, campo, IA, terreno.
- **Guardado:** migración v1/v2 → v3, corrupto → respaldo, 3 slots (`02_GUARDADO_Y_DATOS.md` §6).
- **Determinismo:** misma semilla + mismas decisiones = misma batalla y mismo mundo.
- **Datos:** todo JSON pasa su validador y sus cruces (`../DATOS.md`).
- **Escenas:** pintura y navegación, sin simular (regla 2).

---

## 4. Prueba manual (10 minutos)

1. Crear partida → prólogo → primer sitio.
2. Guardar, salir, cargar (comprueba migración y slots).
3. Una batalla completa hasta la ruptura de moral.
4. Un fin de batalla con las 4 salidas.
5. Abrir el registro y la tienda y volver al mundo.

- **0 errores en consola** y **sin atascos**; si algo bloquea, es **bug ALTA** (`../BUGS.md`).

---

## 4b. Navegación en vivo (MCP) — al cerrar cada fase

- **Regla (2026-10-02, `../../AGENTS.md`):** además del humo, **al final de cada fase** (y de
  cada paso con hito jugable) se hace una **prueba de navegación en vivo** del juego servido,
  no solo la batería headless.
- **Servidor:** `npm run serve` (puerto 8123) y el juego abierto en el navegador.
- **MCP de navegador del entorno** (instalados en la máquina, fuera del repo):
  - **`cdp-browser-mcp-server`** → `/root/cdp-browser-mcp-server/mcp-server` (`node dist/index.js`):
    conecta por WebSocket al Chromium **ya en marcha** (`chromium --remote-debugging-port=9222`).
  - Alternativas instaladas: **Playwright MCP** (caché en `/root/.cache/ms-playwright-mcp`) y
    **chrome-devtools-mcp**; se usa la que el entorno exponga como herramienta.
- **Qué se navega en vivo:** portada → menú → creación → **exploración** (caminar, mirar,
  entrar y salir de un sitio, guardar) → carga desde menú; además idioma EN/ES en caliente,
  opciones persistidas, y **0 errores de consola** durante todo el recorrido.
- **Si la sesión no expone MCP de navegador:** se ejecuta al menos `npm run smoke` (Chromium
  real, 2 tamaños), se anota en la tarea que el paso quedó verificado por humo, y la
  navegación MCP queda **pendiente para el cierre de fase** (nunca se da una fase por cerrada
  sin una de las dos).
- **`npm run vivo` (2026-10-02, paso 1.1):** cuando el MCP no está como herramienta, el repo
  trae la prueba de navegación en vivo ella misma: `tools/live_check.mjs` (guion) +
  `tools/cdp.mjs` (cliente CDP mínimo, sin dependencias). Levanta el servidor, arranca
  Chromium con `--remote-debugging-port` y **conduce el juego** como un jugador: portada →
  menú (armado de «nueva partida») → creación (dificultad, nombre, 7 puntos, origen) →
  exploración (**comprueba que el sitio se construye**, camina con la palanca, gira
  arrastrando, deja que el autopiloto encuentre el umbral, lo cruza, comprueba que el sitio
  cambia y que se guarda) → recarga y **continuar** (mismo sitio) → opciones e idioma en
  caliente. Termina exigiendo **0 errores de consola y 0 rechazos silenciosos**, y deja
  capturas en `coverage/tmp/vivo/`.
  - Dos ideas hacen que la prueba no mienta: (1) compara **estado y píxeles**, no solo
    que la consola esté limpia; (2) con `?debug=1` la escena publica `globalThis.__eb.estado()`
    (`js/scenes/sc_exploracion.js`), y sin ese flag no existe.
  - **Ya detectó un bug real:** al continuar una partida se arrancaba en el primer sitio y
    además se guardaba ese por error (el sitio pedido se leía antes de que llegaran los datos).
- **Desde 2026-10-03 entra en `npm run qa`** (la puerta rápida incluye el recorrido real; `qa`
  tarda ~1 min más). El MCP del entorno sigue siendo **el paso manual del cierre de fase**.

---

## 5. Criterio de terminado (DoD)

1. `npm run qa` **verde**.
2. **Hito jugable** cumplido (`01_FASES.md` §2).
3. **Guardar/cargar** intacto + migración probada.
4. **0 errores** de consola en el recorrido (`npm run vivo`, ya en el QA) y **humo** en dos tamaños.
5. **Documento actualizado** en la misma tarea que cambia el diseño.

**Además, al cerrar una fase** (no cada tarea): la **prueba manual de 10 min** del §4 y la
navegación con MCP (§4b).
